# CR-006: Proposed AI/ML-Powered Operational Insights

| Field | Detail |
|---|---|
| Requested by | Mutshidzi Nduvheni |
| Date | 19/10/2026 |
| Requested change | Introduce AI or Machine Learning (ML) capabilities to analyse CivicConnect operational data and identify trends, recurring issues, service request patterns and potential inefficiencies. The system could provide management with automated insights alongside existing charts and reports. |
| Reason / expected value | As CivicConnect's user base grows, the increasing volume of operational data may become difficult to analyse manually using charts alone. ML could identify less obvious patterns, highlight recurring service issues and provide meaningful insights to support informed, data-driven management decisions. This could improve the efficiency of understanding CivicConnect's operations and identifying areas for improvement. |
| Requirements affected | New functional requirements would be needed for automated insights, trend detection and reporting. Non-functional requirements would need to address accuracy, performance, reliability and explainability. The RTM would require updates if the change were approved. |
| Architecture/design affected | The existing modular monolith with layered architecture would need to be assessed for ML integration. Additional services or modules for data preparation, analysis and insight generation may be required. Architecture diagrams, design decisions and potentially new ADRs would need updating. |
| UI/API/data affected | The management interface would require new components to display generated insights. Additional API endpoints or services may be needed. The existing database and data-processing workflow would need to be assessed to determine whether the available data is sufficient for meaningful analysis. |
| Security/privacy impact | Data processing must comply with POPIA. Personal information should be minimised or anonymised where appropriate. Access to management insights must follow the existing role-based access control model. External AI/ML services would require additional privacy and security assessments. |
| Quality/testing impact | Additional unit, integration, API and end-to-end tests would be required. The team would need to validate the accuracy and usefulness of generated insights, handle insufficient or inconsistent data, and assess performance with larger datasets. |
| Scope impact | High. The change introduces functionality outside the agreed scope and affects multiple artefacts, including the PED, RTM, architecture documentation, risk register, UI, API, database and testing documentation. This creates a significant risk of scope creep. |
| Schedule/resource impact | High. The three-person team has limited capacity to research, design, implement and test ML capabilities within the existing deadline. The additional work could delay the completion and verification of current requirements. A future release would provide more realistic implementation time. |
| Cost impact | Potential additional costs for AI/ML services, hosting, storage, processing and monitoring. Costs would depend on the chosen technology and deployment approach. Open-source solutions could reduce licensing costs but would still require development and maintenance effort. |
| Risk impact | Increased risk of scope creep, schedule delays, incomplete requirements, inaccurate insights, privacy violations and technical complexity. The available operational data may also be insufficient to generate reliable patterns. |
| Recommendation | REJECT |
| Approved by | Tinyiko, Thabang |
| Rationale | AI/ML could provide long-term value by helping management identify operational trends and patterns that may not be apparent from charts alone. However, the capability is not essential to the current release and would introduce substantial additional requirements, architectural changes and testing work. Given the three-person team and existing deadline, the change should be deferred until a future release. The current baseline should be completed and verified first, after which the proposal can be reassessed using actual operational data and management feedback. |
