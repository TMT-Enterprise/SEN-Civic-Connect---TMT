# CR-001: Adding FR-017 in requirements

| Field | Detail |
|---|---|
| Requested by | Tinyiko Siwele |
| Date | 22/09/26 |
| Requested change | Add FR-017, allowing authorised admins to add, update, and delete service category options. The system must prevent duplicate categories, ensure at least one category remains, and make category changes available to requesters. |
| Reason / expected value | Allows staff/management to maintain service categories as the organisation's needs change without requiring developers to modify the system. This improves flexibility and ensures requesters always have up-to-date category options. |
| Requirements affected | FR-017 is added. Existing requirements relating to service requests and category selection may also need to reference the dynamically managed category list. |
| Architecture/design affected | The system design must support persistent category data and CRUD operations for categories. The service-request component should retrieve available categories rather than relying on hard-coded options. Authorisation must restrict category management to admins. |
| UI/API/data affected | UI: Add an admin category-management interface and ensure the requester form displays the current categories. API: Add endpoints for creating, updating, retrieving and deleting categories. Data: Add/use a persistent ServiceCategory table/entity with a uniqueness constraint to prevent duplicate categories. |
| Security/privacy impact | Category management must be restricted to authorised admin users. |
| Quality/testing impact | Add tests for adding, updating and deleting categories; duplicate-category validation; preventing deletion of the final remaining category; authorisation; and confirming that changes appear in requester category options |
| Scope impact | Moderate scope increase. Adds admin functionality, API operations, persistent category management and additional validation/testing |
| Schedule/resource impact | Requires additional development, database, UI and testing effort |
| Cost impact | n/a |
| Risk impact | Introduces risks such as unauthorised category changes, duplicate data, deletion of the final category, and inconsistencies between admin-managed categories and requester forms. |
| Recommendation | ACCEPT |
| Approved by | Thabang, Mutshidzi |
| Rationale | FR-017 provides useful administrative flexibility and can be implemented within the existing system architecture. The change has a moderate scope impact but does not require a fundamental architectural change. The requirements can be controlled through role-based authorisation, persistent category data, validation and testing. |
