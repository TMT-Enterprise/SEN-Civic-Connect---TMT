# CR-004: Adopt Short-Lived Issue-Linked Branches

| Field | Detail |
|---|---|
| Requested by | Tinyiko Siwele |
| Date | 30/09/2026 |
| Requested change | Update the CivicConnect GitHub governance method to require short-lived branches created for individual GitHub Issues, with each branch linked to its corresponding issue and merged into main through a pull request. A standard PR format shall be used to provide a consistent description of the change. |
| Reason / expected value | The previous dedicated development branch per member allowed multiple tasks to be combined across PRs, reducing traceability and potentially causing previously reviewed changes to be reviewed again. Using a short-lived branch for each issue/task creates a clear one-task-to-one-branch-to-one-PR relationship, keeping changes focused, improving traceability, and reducing unnecessary re-reviews. |
| Requirements affected | none |
| Architecture/design affected | none |
| UI/API/data affected | none |
| Security/privacy impact | none |
| Quality/testing impact | Pull requests shall include a standard checklist covering relevant areas such as functionality and test results. Smaller PRs should make critical review and verification more practical. |
| Scope impact | Process/ governance scope will be updated. |
| Schedule/resource impact | Minimal effort is required to create and close and issue-specific branch. |
| Cost impact | none |
| Risk impact | Reduces risk of untraceable changes, unrelated tasks being combined, oversized pull requests and unnecessary repeated reviews. However, contributors may fail to correctly link branches, issues and PRs; this can be mitigated through standard naming conventions. |
| Recommendation | ACCEPT / MODIFY / DEFER / REJECT |
| Approved by | (two reviewers, names) |
| Rationale | This proposal is backed by assignment 2 findings which identify that concise PRs are easier to review and short-lived branches prevents unrelated work from accumulating on the same branch. The branch shall be named using the issue identifier, for example `feature/23-user-registration`. The resulting pull request shall reference the same issue and follow the agreed PR format. Where appropriate, the PR description shall use GitHub closing syntax such as `Closes #23`, allowing the issue to be automatically closed when the PR is merged. |
